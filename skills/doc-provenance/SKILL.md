---
name: doc-provenance
description: Use when adding or auditing source citations, attribution, licenses, version/date metadata, support status, limitations, or planned-work records in documentation.
---

Read the documentation contract. Trace factual claims, mathematical results,
borrowed examples, adapted skills, package dependencies, and generated output
to authoritative sources. Record URLs or repository paths, access/review date,
license/attribution constraints, project version, support status, limitations,
and planned work without claiming more than the evidence supports.

Keep provenance close to the claim or in a linked source register. Do not add
licenses from inference; preserve the repository's actual license and flag
ambiguity. Distinguish current behavior, planned behavior, and historical
context. Pair factual changes with the repository's citation checker when one
exists.

Return changed paths, source-to-claim mapping, verification evidence, and
unresolved provenance or licensing questions.
