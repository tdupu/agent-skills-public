---
name: doc-repository
description: Use when creating or repairing repository-level documentation, contributor guidance, architecture notes, operations pages, or a linked documentation index.
---

Read the documentation contract and repository policies. Inventory the README,
contributor/agent instructions, API/reference pages, examples, tests, release
notes, license, citation, support status, roadmap, and build/test commands.

Create a small navigation graph with one canonical home per topic. Make the
top-level path answer what the project is, who it is for, how to acquire and
use it, how to verify it, how to contribute, and where limitations/plans live.
Link rather than duplicate. Keep private workflow details out of public docs.

Use `doc-quickstart`, `doc-examples`, `doc-navigation`, or `doc-provenance`
for focused edits. Return the graph, changed paths, checked links, commands,
and unresolved orphan/stale pages.
