---
name: using-docpowers
description: Use when creating, repairing, auditing, or organizing documentation for repositories, packages, skills, packs, APIs, or mathematical projects.
---

Invoke `using-superpowers` once and reuse the active coordinator. Read
`references/documentation-contract.md`. Preserve existing specialized routes;
choose one primary leaf from observable evidence, then compose a test leaf only
for executable examples. Never recursively invoke `using-testpowers`.

| Evidence in the request or repository | Primary route |
|---|---|
| Read-only Mathcity policy audit; Mathcity documentation edit; Magma/Sage package README edit | `check-documentation-policy`; `improve-documentation`; `improve-package-README` |
| Sage, M2, Magma, Lean, or LaTeX layout/toolchain | `doc-math-sage`, `doc-math-m2`, `doc-math-magma`, `doc-math-lean`, or `doc-math-latex` |
| Gas City pack, manifest, generated index, or source registry | `doc-pack-gascity` |
| Claude/Codex skill collection or plugin bundle | `doc-pack-skills` |
| Pack/plugin/package/bundle documentation | `doc-pack` |
| Install, acquisition, configuration, or first useful command | `doc-quickstart` |
| Worked example, tutorial, doctest, or executable snippet | `doc-examples` |
| Public API, declaration, method, command, or error contract | `doc-api` |
| Links, index, parent page, orphan, or canonical-home issue | `doc-navigation` |
| Citation, attribution, license, date, status, limitation, or roadmap | `doc-provenance` |
| Repository-wide creation or repair | `doc-repository` |
| Read-only quality/completeness/freshness audit | `doc-assess` |

For mixed requests, document first and name the test handoff explicitly. Return
changed paths or findings, commands/results, unresolved gaps, and unavailable
toolchains. Keep routers thin and leave detailed procedure to leaves.
