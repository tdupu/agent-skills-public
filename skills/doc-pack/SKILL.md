---
name: doc-pack
description: Use when documenting a distributable package, plugin, skill pack, manifest, bundle, or larger collection of related components.
---

Read the documentation contract. Inspect the manifest/catalogue, source layout,
generated artifacts, builder/release commands, install mechanism, version and
license metadata, attribution, source register, and supported surfaces.

Document acquisition, installation, first use, component discovery, examples,
build/validation, compatibility, provenance, status, limitations, and planned
work. Link each component to its canonical source and explain generated versus
editable files. Check that catalogue names, links, manifests, and packaged
contents agree. Keep pack overview content small; move component detail to
linked pages.

Use `doc-pack-gascity` or `doc-pack-skills` for those layouts. Return changed
paths, manifest/index evidence, bundle verification, and any source/generated
drift.
