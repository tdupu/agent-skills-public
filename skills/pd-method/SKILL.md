# pd-method

The panel wants to know why AI-assisted work here is reliable. The answer is
a procedure, not a model. Explain each tool by what it does for the
mathematics, define each term once, and show one result passing through the
procedure.

## Parts

1. **Who decides**: the PI poses the questions, decides what is kept and what
   is stated as a theorem; agents do breadth work. Say "AI-assisted" and
   "human-driven".
2. **Skills and routing**: what a skill is (a versioned, testable instruction
   set any harness can run); what a routing skill is; the subdomains that
   matter for this proposal (database and webpage tools, manuscript tools,
   formalization tools, computation tools), each in one or two sentences.
3. **Orchestration and context**: the orchestrator (with its real authorship
   and license), the issue tracker that preserves context between sessions,
   gates, and how routine outcomes differ from judgment calls — with one
   concrete example of each.
4. **Records**: what every session records (models, harness, date, prompt,
   inputs and provenance, skills, outputs, checks; token use), from when, and
   how agent text is marked in working notes.
5. **One result traced**: question → breadth → literature → review →
   decision, with dates and counts from the records.
6. **Long-running work** where it exists: what the PI specified and what the
   agents built and tested.
7. **Due diligence**: what was checked, against what, and that stated
   theorems are PI-checked.

## Rules

- Describe only what exists; do not claim a pipeline step (e.g. pull-request
  review) the repository history does not show.
- No volume brags; unreliable output is a failure of procedure.
- Cite released tools as software; name private ones without links.
